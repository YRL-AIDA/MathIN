Отмечает следующие проблемы:

- Формальное построение доказательств

Далее обсуждается связка математических рассуждений и оптимизации. Здесь задачи имеют особенность их нужно постоянно уточнять (итерации).

Что они уже умеют:

- Переводить естественный язык в математическую формулировку
- Выделяют постановки
- Подсказывают и предлагают эвристики
- Переформулировать одну задачу в другую

Математические задачи следует делить на два вида: математические вычисления и математические рассуждения

### Математические представления

#### Представление чисел

Вопрос как представлять числа, оказывается достаточно значимым

#### Сами вычисления

Вопрос разделение задачи на подзадачи и размера чисел

### Математические рассуждения

Эта область делиться на решение математических задач и на доказательство теорем. Главной проблемой здесь является галлюцинации, а значит ставится задача в верификации

#### Решение задач

- **MathPrompter** — GPT-3 DaVinci для текстовых задач.

- **Rejection Sampling Fine-Tuning (RFT)** — улучшение рассуждений.

- **MetaMath** — генерация синтетических задач для самоулучшения.

- **WizardMath** — эволюционная инструкционная настройка.

- **MathAttack** — проверка устойчивости к adversarial-примерам.

- **LLEMMA** — открытая LM для математики.

#### Доказательство теорем

- **GPT-f** — генерация стратегий доказательства. (S. Polu, I. Sutskever, Generative language modeling for automated theorem proving, 2020. arXiv:2009.03393.)

- **NaturalProofs** — корпус для оценки моделей доказательства. (S. Welleck, J. Liu, R. Le Bras, H. Hajishirzi, Y. Choi, K. Cho, Naturalproofs: Mathematical theorem proving in natural language, in: NeurIPS Datasets and Benchmarks Track (Round 1), 2021..)

- **DeepMath, INT** — оценка обобщения (G. Irving, C. Szegedy, A. A. Alemi, N. Eén, F. Chollet, J. Urban, Deepmath-deep sequence models for premise selection, NeurIPS 29 (2016). JournalPre-proof).

- **CoqGym** — датасет человеческих доказательств (K. Yang, J. Deng, Learning to prove theorems via interacting with proof assistants, in: ICML, 2019, pp. 6984–6994.).

- **ASTactic** — автоматическая генерация тактик (K. Yang, J. Deng, Learning to prove theorems via interacting with proof assistants, in: ICML, 2019, pp. 6984–6994.).

- **LLEMMA** — автоформализация и предсказание тактик. (Z. Azerbayev, H. Schoelkopf, K. Paster, M. D. Santos, S. McAleer, A. Q. Jiang, J. Deng, S. Biderman, S. Welleck, Llemma: An open language model for mathematics, arXiv preprint arXiv:2310.10631 (2023).)

Далее обсуждается PLM для этих задач. На уровне архитектуры подачи токенов (раздел 3)

Для топовых моделей свойственно иметь длинный контекст.

Подводя к оптимизационным задачам, вывод в том, что оптимизация - это серия задач:

```
Неформальное описание → Формальное моделирование → Выбор солвера → Поиск → Пост-анализ
```

Часть из них хорошо работает, а другая нет.

1. LLM переводят неформальные спецификации в структурированные оптимизационные модели:

- идентификация переменных решения,

- целевой функции,

- ограничений.

2. LLM помогают:

- находить пропущенные ограничения,

- устранять избыточные переменные,

- исправлять плохое масштабирование,

- предлагать valid inequalities и реформулировки.

Точная допустимость и оптимальность остаются за классическими солверами

3. В крупномасштабных и комбинаторных задачах LLM могут:

- генерировать качественные начальные решения,

- предлагать начальные предположения,

- настраивать параметры,

существенно снижая усилия поиска при взаимодействии с точными или эвристическими солверами.

4. После решения LLM:

- суммируют trade-offs,

- объясняют активные ограничения,

- переводят числовые результаты в actionable insights для лиц, принимающих решения.

Открытые проблемы:

1. Галлюцинации
2. Мультимодальность (особенно изображения, графики)
3. Нет достаточно хорошей метрики
4. Творческие задачи
5. Область образования
6. Наборы данных, больших нет
7. Работа со сложными реальными задачами
